# Recent phase1 budget 2：阶段单请求最优

> 后续相邻点 budget1 又取得正收益；当前最终推荐见
> `20260819_25_phase1_budget1.md`。本文件保留 budget4→budget2 的独立验收证据。

## 改动与保留边界

新增独立 preset：
`k2_dynamic_f16_3080_active14_phase1_recent_t32_b2`。它完整继承已保留的 t32/recent
配置，只把 `predictive_phase1_budget` 从 4 降到 2：

- phase1 仍从上一轮 recent verify route index 选候选；
- 每轮只提交排序最前的 2 个，而不是 4 个；
- verify prefetch budget 仍为 2，active cache、LRU、segment16 均不变；
- 动态 K1/K2 仍是 0.97 `first_increase`，sampling 与 CPUInfer 算子不变；
- 原 budget4/t32、recent-t16、active14 和 full-context-safe preset 全部保留。

动机来自 recent phase1 的 lifecycle 分析：budget4 的消费率已经从旧 frequency 路径的
11.66% 提高到 72.92%，但每轮仍可能为排名 3--4 的候选产生额外换入、换出和 cache
竞争。budget2 与 verify boundary 的既有预算一致，是最小的收紧候选。

## 一条真实请求 TPOT

配置为 MMLU-Pro validation 第 0 条、seed 20260719、512 固定输出、temperature 0.6、
single-weight F16、CPUInfer 32 threads / 2 x 16 NUMA pools，所有 profiling 关闭：

| phase1 budget | TPOT | decode rounds | mean round wall | validation |
|---:|---:|---:|---:|:---|
| 4（现有 t32） | 59.673 ms | 261 | 116.830 ms | 512 token，valid |
| **2** | **55.169 ms** | **255** | **110.555 ms** | 512 token，valid |
| 变化 | **-4.503 ms / -7.55%** | -6 | **-6.275 ms / -5.37%** | 无错误 |

输出从第 63 个 token 起分叉，因此不能把全部差值严格归因于 budget；但候选同时减少
decode rounds 和平均 round wall，方向也与“减少低排名 phase1 换入/竞争”的机制一致。
按用户要求的一条真实请求正收益门禁，作为独立 preset 保留。

该结果比 `296cf59 + active14` 同日复跑锚点 56.846 ms/token 低 1.677 ms（**-2.95%**），
是截至本提交同一验证口径的新单请求最佳点。它仍只是 stochastic 单请求，不替代未来
多 seed/holdout 的稳健性结论。

结果目录：

- budget2：`results/tpot_phase1_recent_t32_budget2_20260819/`；
- budget4：`results/tpot_phase1_recent_t32_20260819/`；
- 同日旧锚点：`results/tpot_ab_active14_formal_20260819/best/`。

## 同轮否决点

### 动态门限 0.98

在其它配置完全相同的情况下，把 K1→K2 predictor 门限从 0.97 提高到 0.98，单请求为
61.020 ms/token、270 rounds，相对 0.97/t32 回退 **2.26%**。不新增 0.98 preset，现有
0.97 动态配置继续作为 fallback。结果位于
`results/tpot_phase1_recent_t32_threshold098_20260819/`。

### CPUInfer `m_block`

以 exact-Nano 参数（F16 expert/BF16 hidden、group_min=1、t32/2 NUMA、50% CPU routes）
扫描 m1/2/4/8/16/32/64/128。m4 与当前 m32 最接近：qlen1 快 0.22%、qlen2 慢
0.08%、qlen3 快 0.11%，综合差异约 0.04%，已落入独立进程波动范围；其它点也没有
跨 qlen 的清晰优势。因此保持 m32，不运行缺少信号的端到端候选。分析结果位于
`results/analysis_cpuinfer_nano_mblock_20260819/`。

## 验证

- preset 解析测试锁定 budget2、t32/双 NUMA、recent selector、0.97 动态门限；
- fixed grouped-GEMM 环境与父 preset 一致；
- 一条 512-token 请求输出长度和 validation 均通过；
- benchmark metadata 确认 `predictive_phase1_budget=2`、`kt_num_threads=32`。

## 一句话总结

recent phase1 每轮只预取前 2 个候选，使当前 t32 动态配置从 59.673 降至
55.169 ms/token，并以 2.95% 超过同日旧全局锚点，同时保留全部旧配置 fallback。
