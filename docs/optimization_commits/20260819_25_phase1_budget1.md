只把 `predictive_phase1_budget` 从 2 收紧到 1。每轮 phase1 仍使用 recent verify index，

fallback，不覆盖、不改名。

## 一条真实请求 TPOT

MMLU-Pro validation 第 0 条、seed 20260719、512 固定输出、temperature 0.6、
single-weight F16、所有 profiling 关闭：

| phase1 budget | TPOT | decode rounds | mean round wall | validation |
|---:|---:|---:|---:|:---|
| 4（t32 父配置） | 59.673 ms | 261 | 116.830 ms | 512 token，valid |
| 2（直接前序） | 55.169 ms | 255 | 110.555 ms | 512 token，valid |
| **1** | **53.726 ms** | 261 | **105.187 ms** | 512 token，valid |
| b1 相对 b2 | **-1.443 ms / -2.62%** | +6 | **-5.368 ms / -4.86%** | 无错误 |
| b1 相对 b4 | **-5.947 ms / -9.97%** | 0 | **-11.643 ms / -9.97%** | 无错误 |

b1 与 b2 从第 63 个 token 起分叉，b1 与 b4 从第 122 个 token 起分叉，因此仍不能把
全部单请求差值作严格因果值。更强的证据是：即使 b1 比 b2 多 6 个 decode rounds，平均
round wall 仍下降 4.86%；与 rounds 相同的 b4 相比，TPOT 和 round wall 都下降 9.97%。
这与减少 phase1 transfer/cache 竞争的假设一致，但 profile 关闭时没有 lifecycle 分项，
机制结论仍标为推断。

b1 比 `296cf59 + active14` 同日锚点 56.846 ms/token 低 3.120 ms（**-5.49%**），刷新
当前同口径单请求最佳。结果位于
`results/tpot_phase1_recent_t32_budget1_20260819/`；直接前序为
`results/tpot_phase1_recent_t32_budget2_20260819/`。

## budget0 边界点

同配置完全关闭 phase1（budget0）后为 55.248 ms/token、262 rounds、107.755 ms mean
round wall；相对 b1 回退 **1.522 ms / 2.83%**，round wall 也回退约 2.44%。输出从第
21 个 token 起分叉，但 TPOT 与每轮成本方向一致。它说明最高排名的一个 recent phase1
候选仍有净价值，最优点不是完全关闭；因此不新增 b0 preset，结果保存在
`results/tpot_phase1_recent_t32_budget0_20260819/`。

## 验证

- preset 测试锁定 budget1、recent selector、t32/2 x 16 NUMA 与 0.97 动态门限；
- 继承 fixed grouped-GEMM 环境；
- summary 确认实际 `predictive_phase1_budget=1`、512 token、validation 通过；
- budget0 相邻边界点完成一条相同请求并因回退 2.83% 被否决；
- 所有父 preset 均保留，可按 workload 回退。

## 一句话总结

recent phase1 只保留最高排名的一个候选，将 TPOT 从 budget2 的 55.169 继续降到
53.726 ms/token，成为新单请求最优，同时保留 budget2/budget4 和全部动态配置 fallback。
