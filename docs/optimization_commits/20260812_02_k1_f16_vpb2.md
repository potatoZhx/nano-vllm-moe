# F16 K1 + verify-prefetch budget 2

## 选择依据

在 single-weight 可稳定承载 F16 后，对固定 draft length K1-K6 做同口径筛选。256-token
screen 的 TPOT 为：K1 `75.959`、K2 `85.613`、K3 `83.984`、K4 `90.728`、
K5 `109.542`、K6 `103.703` ms/token。当前机器没有原生 BF16/AMX，F16 llamafile
kernel 更合适；K1 还使 verify 固定落在 qlen=2 的低开销路径。

K1 下 verify-prefetch budget 0/1/2/4 分别为 `85.317`、`78.949`、`72.317`、
`75.959` ms/token（256 输出），因此选择 vpb2。16 threads 也优于 20 threads
（`72.317` vs `78.227` ms/token）。

配置已固化为 `--optimized-config k1_f16_3080`：F16、K1、vpb2、16 CPU threads、
2 NUMA pools、cache ratio 0.075、verify bucket 2。

## 三次独立 512-token 复测

结果目录：`results/single_weight_f16_k1_vpb2_512_repeats3/`。

| repeat | TPOT (ms/token) |
|---:|---:|
| 0 | 69.682 |
| 1 | 73.837 |
| 2 | 70.689 |
| mean | **71.403** |
| population std | 1.770 |

相对 single-weight BF16/K3 `91.287`，均值降低 `21.8%`（`1.28x`）；相对文档中的
ktransformers BF16 `122.35`，降低 `41.6%`（`1.71x`）；相对本日同 prompt 的
ktransformers F16 stable replay `125.886`，降低 `43.3%`（`1.76x`）。保守地与历史
ktransformers F16 最好值 `81.90` 比较，仍降低 `12.8%`（`1.15x`），但该历史值的
prompt/tokenizer/log retention 不同，不能视为完全同口径。

三次均生成固定 512 token 并通过 output-length validation。TPOT 定义为
`decode_wall_sec / (generated_output_tokens - 1)`。
